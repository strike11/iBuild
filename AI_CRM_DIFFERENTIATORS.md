# CRM-помощник iBuild: зачем он нужен и чем отличается от других

Когда в CRM пишут «AI», обычно имеют в виду одно из двух. Либо обученную модель, которая выдаёт менеджеру число от 0 до 100 и никак не объясняет, откуда оно взялось. Либо чат-бота на большой языковой модели, у которого можно спросить что угодно — и который может уверенно сообщить цифру, которой в базе нет.

У нас другое. Помощник состоит из двух частей, и обе написаны обычным кодом на Dart в файле [`server/lib/src/ai/lead_scoring_engine.dart`](server/lib/src/ai/lead_scoring_engine.dart):

- **Оценка заявок** — считает по явным правилам, насколько заявка горячая, и всегда перечисляет, из чего сложилась оценка.
- **Помощник по кнопкам** (`CrmQueryEngine`) — отвечает на типовые вопросы менеджера, но не свободным текстом, а готовыми разделами с реальными цифрами.

Ни одна из частей не обращается к внешней модели. Ничего не обучается, ничего не генерируется — только расчёт по данным, которые уже есть в системе.

---

## Какие задачи это решает

У менеджера застройщика два вопроса каждый день.

**Первый: кому звонить прямо сейчас?** Заявок много, время ограничено, и по списку «все новые сверху» непонятно, кто из них реально готов купить. Помощник расставляет заявки по приоритету и рядом с каждой пишет, почему она наверху.

**Второй: что вообще происходит в продажах?** Сколько заявок пришло, кто ждёт ответа дольше нормы, как загружены менеджеры, где отваливаются люди в воронке, какие квартиры спрашивают чаще всего. Помощник отвечает на это по кнопкам, а не требует лезть в отчёты.

Сервер отдаёт только числа и коды строк — сам текст интерфейса подставляет приложение (`b2b/lib/features/ai_crm/`), поэтому всё работает на трёх языках без правок на сервере. Обращения: `GET /v1/ai/crm/leads` и `POST /v1/ai/crm/query`.

---

## 1. Оценка всегда объясняет себя

**Как у других.** Модель выдала 74 — почему 74, не знает никто, включая того, кто её внедрял. Проверить нельзя, оспорить нельзя, объяснить клиенту или проверяющему тоже нельзя.

**Как у нас.** Оценка складывается из понятных слагаемых, и каждое слагаемое сразу подписывается. Заявка на покупку строящегося жилья добавляет больше, чем заявка на аренду. Указана конкретная квартира — плюс. Человек написал развёрнутое сообщение вместо «интересует» — плюс. Не указал ни квартиру, ни удобное время, ни подробностей — минус, и это тоже отмечается отдельно.

```dart
// server/lib/src/ai/lead_scoring_engine.dart
switch (intent) {
  case 'buy_offplan':
    points += 22;
    reasons.add('highIntent');
    reasons.add('offplanInterest');
  case 'buy':
    points += 18;
    reasons.add('highIntent');
  case 'viewing':
    points += 20;
    reasons.add('viewingRequested');
  // ...
}
```

Границы категорий тоже жёстко заданы: 70 и выше — горячая, от 40 до 69 — тёплая, ниже — холодная.

В итоге менеджер видит не просто «86», а «86, потому что человек хочет купить конкретную квартиру, оставил подробное сообщение, и мы уже просрочили ответ». Такую оценку можно проверить, можно с ней не согласиться, и её не стыдно показать при проверке.

Отдельно движок читает само сообщение и ищет в нём слова про ипотеку, наличные и срочность — сразу на трёх языках, русском, узбекском и английском. «Срочно», «shoshilinch», «urgent» — для системы это одно и то же.

---

## 2. Учитывает то, что происходит на стройке, а не только клики в почте

**Как у других.** Заявку оценивают по маркетинговым признакам: откуда пришёл, открыл ли письмо, сколько страниц просмотрел.

**Как у нас.** Кроме поведения человека, движок смотрит на состояние самого проекта.

Если в жилом комплексе, который человек спрашивает, осталось меньше 15% свободных квартир — заявка поднимается. Дефицит означает, что тянуть нельзя: то, что человек хочет, вот-вот закончится.

Если по этому же комплексу за последнюю неделю пришло пять и больше заявок — это отдельный сигнал: комплекс разогрелся, спрос идёт волной, и работать по нему нужно быстрее, даже если конкретная заявка выглядит спокойной.

```dart
// server/lib/src/ai/lead_scoring_engine.dart
if (available / units.length < 0.15) {
  points += 8;
  reasons.add('unitScarcity');
}
// ...
if (recentProjectLeads >= 5) {
  points += 6;
  reasons.add('hotProject');
}
```

Ещё одна проверка — по номеру телефона: если с этого же номера уже приходили заявки раньше, человек возвращается, и это тоже повод поднять его выше.

## 3. Показывает не только горячих покупателей, но и тех, о ком забыли

Это то, чего в обычных системах оценки заявок нет вообще. Заявку теряют не потому, что она была плохая, а потому, что до неё никто не дошёл вовремя.

Движок считает время и отдельно поднимает такие случаи:

- новая заявка без ответа больше двух часов — нарушен норматив ответа;
- сутки прошли, а с человеком так и не связались;
- три дня прошло, и по-прежнему тишина;
- заявка застряла в одном статусе больше трёх дней.

```dart
// server/lib/src/ai/lead_scoring_engine.dart
if (status == 'new' && age.inMinutes > _kSlaMinutes) {
  points += 15;
  reasons.add('slaBreach');
}
if (stillWaiting && lastContactAt == null) {
  if (age.inDays >= 3) {
    points += 18;
    reasons.add('noResponse3d');
  } else if (age.inHours >= 24) {
    points += 10;
    reasons.add('noResponse24h');
  }
}
```

Обычная CRM в этой ситуации просто покажет статус «новая» и промолчит. Наш помощник поднимает такую заявку наверх, потому что упущенное время — это отдельный риск, не связанный с тем, насколько хорош покупатель.

---

## 4. Решение остаётся за человеком

Если менеджер сам поставил заявке оценку, система её **не перезаписывает**. Расчёт уходит в отдельные поля, и в интерфейсе ручная оценка всегда важнее автоматической.

```dart
// server/lib/src/ai/lead_scoring_engine.dart
/// the manual `score` field is never touched, so it keeps winning in the UI.
```

Разница принципиальная. Мы не строим систему, которая указывает менеджеру, кому звонить. Мы строим систему, которая раскладывает заявки по приоритету, объясняет свою логику — и уступает, если человек видит ситуацию иначе.

---

## 5. Помощник ведёт по разделам, а не отвечает свободным текстом

`CrmQueryEngine` — не чат. У менеджера нет поля ввода, где можно спросить что угодно. Есть примерно двадцать готовых разделов: горячие заявки, что делать дальше, кто ждёт ответа, никому не назначенные, сводка за сегодня, разбор по комплексу, по менеджеру, аналитика, конверсия, спрос по комнатам.

Каждый раздел — это обычная функция, которая берёт доступные пользователю заявки и считает по ним ответ. Ничего не запоминается между запросами, путь «где я сейчас нахожусь» вычисляется из структуры дерева.

```dart
// server/lib/src/ai/lead_scoring_engine.dart
/// Guided option-tree backend for `POST /v1/ai/crm/query` (plan Part 3 "b2b
/// assistant" — not free chat). Every node is a pure function of
/// `(node, params, leadsInScope)`; the tree is fixed and shallow enough that
/// `breadcrumb` can be derived structurally, so the server stays stateless.
```

Звучит скромнее, чем «спросите у ИИ что угодно», но у этого есть важное следствие: **помощник физически не может ничего выдумать**. Он не сочиняет текст. Он возвращает посчитанные числа и код строки, которую подставит приложение. Заявки, которой нет в базе, в ответе не появится никогда.

## 6. Показывает спрос рядом с остатками

Это уже не про отдел продаж, а про самого застройщика.

Разделы «спрос» считают, квартиры с каким числом комнат люди спрашивают чаще всего — и ставят рядом, сколько таких квартир в комплексе ещё свободно.

```dart
// server/lib/src/ai/lead_scoring_engine.dart
/// Room mix asked for inside a single project, next to how many of those
/// homes are still available there — demand and supply side by side.
Map<String, dynamic> _projectDemand(...) {
  final counted = _roomDemand(projectLeads, store);
  final available = <int, int>{};
  // ... count available units by room count ...
  return {
    'cards': [
      ..._demandCards(counted),
      for (final rooms in (available.keys.toList()..sort()))
        _metricCard('crmBot.metric.availableRooms', ...),
    ],
  };
}
```

Из этого сразу видно вещи, которые обычно замечают слишком поздно: трёхкомнатные спрашивают вдвое чаще, чем их осталось, а однокомнатные стоят без движения. Это уже разговор о ценах и о том, что строить дальше, а не только о звонках.

---

## 7. Все цифры считает один и тот же движок

На каждый запрос система пересчитывает заявки заново и отдаёт единый набор показателей:

- сколько заявок пришло за сегодня, за неделю, за месяц — и сколько это от лимита тарифа;
- сколько горячих, тёплых и холодных;
- по каждому менеджеру: сколько заявок в работе, сколько из них горячих, за сколько минут он в среднем отвечает;
- медианное время ответа и сколько раз норматив нарушен;
- воронка по статусам и переход между этапами: новая → связались → назначен показ → был на объекте → готов → сделка.

Поэтому число в списке заявок и число в помощнике всегда совпадают: это не два отчёта, которые кто-то когда-то согласовывал, а один расчёт.

## 8. Не выглядит сломанным у нового застройщика

Обычная проблема свежего аккаунта: заявок ещё нет, и любой раздел показывает нули. Человек смотрит на пустой экран и делает вывод, что инструмент не работает.

Помощник в этом случае подставляет наглядные примеры и явно помечает их как примеры — чтобы было понятно, как раздел выглядит с реальными данными.

```dart
// server/lib/src/ai/lead_scoring_engine.dart
/// Sample answer for a workspace that has no leads yet.
Map<String, dynamic> _withExampleFallback(...) {
  if (hasLeads) return answer;
  final cards = _exampleCards(node);
  if (cards == null) return answer;
  return {
    ...answer,
    'messageCode': 'crmBot.example.message',
    'isExample': true,
    'cards': cards,
  };
}
```

При этом у примеров нет ни идентификаторов, ни кнопок «открыть» и «взять себе» — перепутать пример с настоящей заявкой невозможно, даже случайно.

---

## 9. Работает мгновенно и ничего не стоит за запрос

Как и умный поиск, помощник — это обычный расчёт по данным, которые уже лежат в системе. Нет обучения, нет обращения к OpenAI, нет ожидания ответа стороннего сервиса и нет оплаты за каждый клик менеджера. Это написано в первых строках файла:

```dart
// server/lib/src/ai/lead_scoring_engine.dart
/// Deterministic CRM lead scoring — plan Part 3. No LLM: pure computation
/// over `store.leads`, feeding `GET /v1/ai/crm/leads` and
/// `POST /v1/ai/crm/query`.
```

Побочный эффект приятный: одинаковые данные всегда дают одинаковый результат, поэтому поведение помощника можно покрыть тестами — с языковой моделью так не получится.

---

## Коротко

Наш CRM-помощник — не чат про ваши заявки. Это две простые вещи, сделанные честно:

1. **Оценка, которая объясняет себя.** Понятные правила вместо непрозрачной модели, и рядом с каждой оценкой — из чего она сложилась.
2. **Помощник, который не врёт.** Готовые разделы с реальными цифрами вместо свободного текста, который может звучать убедительно и быть неправдой.

А отличают его от типичных решений четыре вещи: он смотрит на остатки квартир и спрос по комплексу, а не только на поведение человека; он поднимает заявки, о которых забыли, а не только перспективных покупателей; он не спорит с решением менеджера; и он показывает застройщику, что люди спрашивают в сравнении с тем, что у него осталось.
